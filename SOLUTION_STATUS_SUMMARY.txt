KEY FACTS ABOUT FSH ARCHITECTURE:

1. VERTICAL SLICE ARCHITECTURE
   ✓ Each module is ONE project (not Domain/App/Infra separation)
   ✓ Features are organized vertically (e.g., Features/v1/Customers)
   ✓ Each feature contains: Command/Query, Handler, Validator, Endpoint
   ✓ Clean separation via folders, not projects

2. MODULE INDEPENDENCE
   ✓ Each module can have its own domain entities
   ✓ NO conflicts from duplicate domain classes
   ✓ Modules are isolated and independently deployable
   ✓ Accounting.Customer != Microfinance.Customer (different entities)

3. SHARED BUILDING BLOCKS
   ✓ All modules depend on BuildingBlocks packages
   ✓ Core provides: DDD primitives, base classes
   ✓ Persistence provides: Repository, Specification
   ✓ Web provides: Endpoint routing, middleware
